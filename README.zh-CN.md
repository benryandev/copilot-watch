# Copilot Watch（简体中文）

[English](README.md)

为 Strike 跟单用户发送 Telegram 提醒：跟单仓位接近强平、带单员已经平仓但你的跟单仍在持有，或者带单员的某笔交易没有被跟单时，你会第一时间知道。

在 Strike Finance 黑客松（2026 年 10 月 22–24 日）期间开发。与 Strike Finance 无关联。不构成投资建议。

**相关工具：**[Copilot Check](https://strike.benryan.com.au) 可以查看一个 Hyperliquid 钱包是否值得在 Strike 上跟单，并在你投入真钱之前先模拟跟单。（目前只有英文版。）

## 开始使用

打开 [@CopilotWatchBot](https://t.me/CopilotWatchBot)，发送 `/start`。

如果你的 Telegram 设置为中文，机器人会自动用中文回复（台湾、香港、澳门的设置会显示繁體中文）。也可以随时切换：`/lang zh`（简体中文）、`/lang tw`（繁體中文）、`/lang en`（English）。Discord 版本目前只有英文。

`/watch` 后面可以加 Strike 地址（`addr1…`）、Strike 昵称，或子账户 ID（Strike 应用 → 子账户 → Account ID → 复制）。使用地址或昵称时，会关注主账户和所有活跃的子账户；在后面加上子账户名称，可以只关注这个子账户（`/watch addr1… Sub1`）。

| 命令 | 作用 |
|---|---|
| `/watch <账户> [子账户名称]` | 开始关注；回复每个账户当前进行中的跟单 |
| `/status` | 当前的跟单仓位、盈亏，以及距离强平还有多远（最近的排在前面） |
| `/settings liq=5` | 强平提醒的阈值，1 到 20%（到 2% 时总会再提醒一次） |
| `/unwatch <账户>` | 停止关注某个账户 |
| `/paper <0x 钱包> [金额]` | 在真正跟单之前，先模拟跟单一个 Hyperliquid 钱包（不用真钱）；只发送 `/paper` 会列出本聊天的模拟跟单。每天布里斯班时间 08:00（北京时间 06:00）会收到一份摘要。 |
| `/lang en`、`/lang zh` 或 `/lang tw` | 本聊天的语言：English、简体中文或繁體中文 |
| `/stop` | 停止全部提醒，并删除本聊天的数据 |

## 提醒内容

大约每 2 分钟检查一次。每个事件只提醒一次（接近强平的提醒在 6 小时后可以再次发送），并说明发生了什么，以及你可以怎么做。`/watch` 之后的第一次检查只记录当前状态，所以过去的记录不会触发提醒。

| | 提醒 | 什么时候发送 |
|---|---|---|
| A1 | 跟单仓位接近强平 | 标记价格距离跟单仓位的强平价格在你设置的百分比以内，到 2% 时再提醒一次。股票和商品合约会附加说明：相关标的市场收盘后，Strike 上的价格仍可能变动，并可能在市场重新开盘时出现跳空。 |
| A2 | 带单员已平仓，跟单仍持有 | 连续两次检查，跟单仓位仍在持有，但带单员在这个市场上已经没有仓位，或者持有的是相反方向。如果带单员是在这个市场被强平，提醒会说明。 |
| A3 | 漏跟的交易 | 带单员在 Strike 上架的市场开了或加了仓，但这个账户在 10 分钟内没有对应的跟单成交（可能是上限、余额或杠杆锁定）。每个市场每小时最多一次。 |
| A4 | 带单员接近强平 | 带单员在 Hyperliquid 上的全仓维持保证金达到账户价值的 60%（Hyperliquid 在 100% 时强平），加密货币账户或股票及商品账户都会检查。 |
| A5 | 带单员转出资金 | 带单员在 24 小时内从 Hyperliquid 账户转出了一半以上的资金（对固定比例跟单很重要，因为跟单规模跟随带单员的权益）。 |
| A6 | 跟单仓位被强平或已结束 | 一笔跟单因强平或自动减仓（ADL）而平仓，或者跟单状态变为已强平或已停止。 |
| A7 | 跟单仓位会比带单员更早被强平 | 跟单仓位距离强平在 20% 以内，而且会比带单员自己的逐仓仓位至少早 2%（按标记价格）被强平，通常是因为带单员开仓后追加了保证金（Strike 会复制杠杆设置，但不会复制之后追加的保证金）。提醒会给出让强平价格和带单员一致所需的保证金。全仓仓位不在此列：它们的强平取决于带单员的整个账户，由 A4 负责。 |

### 收到提醒后怎么做

Copilot Watch 只发送提醒，不会替你操作。要操作需要你的 Strike API 密钥，而 Strike 的密钥可以交易，没有只读选项，所以机器人绝不会索要密钥。请在 Strike 应用中自己操作：追加保证金、减仓、平仓、调整跟单上限，或者保持现状。

## 隐私

只读取 Strike 和 Hyperliquid 的公开数据，不需要 API 密钥，也不需要连接钱包。

每个聊天保存的内容：Telegram 聊天 ID、你关注的账户、提醒阈值和语言，以及每个账户最近 200 条成交 ID 和看到的跟单仓位（都是公开数据）。只有在 Telegram 无法送达时，才会把提醒内容保存最多一小时，以便重新发送；日志只记录数量。`/stop` 会删除本聊天的数据；不再有人关注的账户也会一起删除。使用情况只按天统计总数，不带任何 ID，保存 400 天。

## 限制

- 每个聊天最多关注 5 个账户，每分钟最多 10 条命令。模拟跟单每个聊天最多 3 个。总共最多 300 个聊天（这是一个原型）。
- Strike 的跟单列表最多可能延迟 10 分钟，所以刚开始或刚停止的跟单可能要等一会儿才会显示。
- 跟单上限、排除的市场和杠杆设置不是公开数据，所以漏跟提醒只能说“可能是上限、余额或杠杆锁定”。
- Hyperliquid 按 IP 限流；检查繁忙时，会跳过这一轮的带单员，而不是去猜测。
